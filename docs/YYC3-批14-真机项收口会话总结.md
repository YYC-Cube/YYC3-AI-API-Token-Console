## 四、遇到的问题与解决方案

| 问题 | 解决方案 | 经验教训 |
| --- | --- | --- |
| `browser.contexts()` 启动瞬间为空（TypeError reading 'pages'） | 轮询等待 context 注册；最终改 `launchPersistentContext` 直接返回 context | Chromium 托管启动的 context 注册是异步的，持久化上下文 API 更适合 `--app` 场景 |
| 批13 误查 `newPage()` 页签导致 standalone=false | 改查启动即存在的 app 窗口 page → matches=true | 「媒体查询不可自动化」的结论可能只是探针位置错误，重启攻坚前先复核根因 |
| 真实 Chrome 手动 CDP attach 挂起（批13） | Playwright 托管启动（channel:chrome）规避 | 手动 spawn Chrome + remote-debugging-port 受运行中主实例参数转交影响，托管启动是正道 |
| IDE 对临时脚本报「console is not defined」 | 忽略（缺 node 环境 tsconfig 的诊断噪音），脚本用后即删 | 临时验证脚本不入库，无需为其配置 lint 环境 |
