## 一、上游许可约束图谱（合规基线）

### 1.1 四上游许可核实结果（2026-09-20 实读 LICENSE 文件）

| 上游 | 许可证 | 关键约束 | 对 YYC³ 的影响 |
| ---- | ------ | -------- | -------------- |
| **hermes-agent** | MIT | 保留版权声明 | ✅ 代码/配置/文档均可借鉴，仅保留声明 |
| **ragflow** | Apache-2.0 | 保留声明 + 标注修改 | ✅ 代码可借鉴（衍生文件头部加声明），规范/思想零约束 |
| **dify** | 修改版 Apache-2.0 | ① 多租户运行需商业授权 ② 前端（web/）LOGO 与版权不可移除 | ⚠️ 后端配置模式可借鉴；**直接部署其前端做多租户 SaaS 需商业授权** |
| **open-webui** | 自定义（BSD 变体 + 品牌条款） | 移除/遮蔽「Open WebUI」品牌即违规；例外：≤50 终端用户/30 天 或 书面授权 | ⚠️ 规范思想可借鉴；**直接部署对外服务需品牌保留或授权** |

### 1.2 借鉴方式四级分层（约束由零到高）

| 层级 | 借鉴方式 | 上游约束 | 运维解耦度 | 本规划默认策略 |
| ---- | -------- | -------- | ---------- | -------------- |
| **L0** | 思想/规范/流程（零代码接触） | 无 | 100% 自主 | ⭐ 首选，占借鉴项 70% |
| **L1** | 配置模式重写（pnpm 策略/CI 配方，用自己的注释与结构） | 无（配置模式不受版权保护，仍重写以防分歧） | 100% 自主 | ⭐ 次选，占 20% |
| **L2** | 代码思想重实现（读懂机制后用 YYC³ 风格重写） | 无（clean-room 重实现） | 100% 自主 | 谨慎使用，占 10% |
| **L3** | 直接拷贝代码（MIT/Apache 源，保留声明） | 声明义务 | 中（版本漂移/审计负担） | ❌ 默认禁止，特例审批 |
| **L4** | 直接部署上游运行（dify/open-webui 整体使用） | 品牌条款/多租户授权 | 低（受制于上游演进） | ❌ 仅内网试点，对外服务前必须评估 |

> **运维解耦铁律**：YYC³ 仓库中不得出现指向上游仓库的代码级依赖（git submodule / 依赖包 / 复制粘贴未声明文件）。借鉴产出物必须以「YYC³ 自有风格 + 自有注释」形态存在，使未来任一上游闭源/改许可/停维护时，YYC³ 的构建、测试、部署链路**零感知**。

### 4.2 L4 直接部署的许可评估卡（对外服务前必填）

| 待评估项 | dify | open-webui |
| -------- | ---- | ---------- |
| 多租户 SaaS | ❌ 需商业授权（工作区=租户定义） | ⚠️ >50 终端用户/30天需书面授权 |
| 品牌移除 | ❌ 前端 LOGO 受保护 | ❌ 品牌条款明令禁止 |

## 五、风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
| ---- | ---- | ---- | -------- |
