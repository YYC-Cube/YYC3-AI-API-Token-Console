## 四、遇到的问题与解决方案

| 问题 | 解决方案 | 经验教训 |
| --- | --- | --- |
| `screencapture` 报 could not create image | 探测后放弃截屏路线，转 a11y | 权限探测先行，避免脚本半途死 |
| `osascript -25211 不允许辅助访问`（基础查询通、UI 树拒） | 用户系统设置授权后轮询复探（45s/75s 两探） | macOS 授权粒度：进程查询与 UI 树访问是两级；授权即时生效无需重启 |
| AppleScript `execution error: 不能获得 "path"`（-1728） | handler 参数 `path` → `pfx` | **`path` 是 AppleScript/System Events 保留字**（POSIX path），handler 形参禁用 |
| 权限弹窗「token.yyc3.vip 想获得…访问此设备上的其他应用和服务」挡住 bip | a11y 定位弹窗「允许」按钮先点掉 | 安装性探测（getInstalledRelatedApps 等）会触发权限弹窗，须先清障 |
| 异 profile 启动报「正在现有的浏览器会话中打开」 | 根因：**macOS Chrome 单进程模型**——所有 profile 共享一个浏览器进程，任何新启动均被转交 | 批13/14 成功正因当时无 Chrome 实例；异 profile 隔离在 macOS Chrome 上不存在 |
| 转交后 launchPersistentContext 崩溃（kill EPERM） | `pgrep -f "user-data-dir=/tmp/b15"` 定位**后台驻留主进程**（安装后 `--no-startup-window` 驻留 + SingletonLock）→ 精确 kill | Chrome 安装 PWA 后可能后台驻留；批14 的 ctx.close() 未杀驻留主进程 |
| AppleEvent 超时（-1712）tell Chrome 取窗口 | 识别为无窗口驻留进程不响应 AppleEvent，转 ps 级进程处置 | AppleEvent 超时 ≠ 挂起，先查目标进程窗口状态 |
| 主窗口原生树稀疏（仅 信息栏容器/新标签页 两元素） | `AXEnhancedUserInterface` 强制 + 多轮重扫均无效 → 定论 Chromium 硬边界 | Chromium browser UI a11y 仅对 VoiceOver 级 AT 客户端构建，osascript 不在其列 |
