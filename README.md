## 📖 项目简介 | Introduction

**中文**：YYC³ AI Family Token Console 是本地闭环多端推理矩阵数据看盘系统 —— 面向 M4 Max + iMac + NAS 集群的实时监控中枢。涵盖监控中心（数据监控 / 一键跟进 / 巡查模式 / 告警规则）、运维管理（操作中心 / 文件管理 / 数据库管理 / 闭环 / 报表导出）、AI 智能（API 矩阵与模型管理 / AI 辅助决策 / AI 诊断）、AI Family（12 小时钟盘 / Family 中心）与系统管理（审计 / 用户 / 安全 / PWA）六大域，以「文档讲 why、代码讲 how」的双轮驱动工程闭环交付。

**English**: YYC³ AI Family Token Console is a local closed-loop multi-device inference matrix dashboard — a real-time monitoring hub for M4 Max + iMac + NAS clusters. It spans six domains: Monitoring Center, Operations Management, AI Intelligence, AI Family, Developer Standards, and System Administration, delivered through a dual-wheel engineering loop of *"docs explain why, code shows how"*.

## 🚀 快速开始 | Quick Start

```bash
# 1. 克隆仓库 Clone
git clone https://github.com/YYC-Cube/YYC3-AI-API-Token-Console.git
cd YYC3-AI-API-Token-Console

# 2. 安装依赖 Install (开发服务器端口: 3030 起)
pnpm install

# 3. 启动开发服务器 Start dev server
pnpm dev            # → http://localhost:3030

# 3'. 局域网可访问 LAN accessible
pnpm dev:host

# 4. 质量门禁 Quality gates
pnpm typecheck      # TypeScript strict 检查
pnpm test           # Vitest 单元测试
pnpm test:coverage  # 覆盖率 (≥80% 门槛)

# 5. 生产构建 + 本地部署 Build & serve
pnpm build          # Vite 生产构建 → dist/
pnpm serve:local    # 零依赖部署服务器 (默认 3118) + Ollama 代理
```

## 🤝 贡献指南 | Contributing

1. **认领任务 Pick an issue**：按 [标签规范](./docs/YYC3-开发者文档/LABELS.md) 筛选 `bug` / `feature` / `documentation`，评论认领。
2. **派生分支 Branch**：`git checkout -b feat/your-topic`（`main` 受保护，禁止 force-push）。
3. **本地门禁 Local gates**：`pnpm typecheck && pnpm test`（与 CI 同款，本地绿 = CI 绿）。
4. **提交 PR**：按 [PR 模板](./.github/PULL_REQUEST_TEMPLATE.md) 勾选自检清单；标题遵循 Conventional Commits（`feat:` / `fix:` / `docs:` / `ci:` …）。
5. **标签必选**：PR 必须携带 1 类型 + 1 模块标签。

> 完整规范见 [CONTRIBUTING.md](./docs/YYC3-开发者文档/CONTRIBUTING.md)；行为准则见 [CODE_OF_CONDUCT.md](./docs/YYC3-开发者文档/CODE_OF_CONDUCT.md)。

## 🏷️ 仓库标签规范 | Labeling Policy

> 完整定义与机器可读清单见 [LABELS.md](./docs/YYC3-开发者文档/LABELS.md) 与 [`.github/labels.json`](./.github/labels.json)（可用 [github-label-sync](https://github.com/Financial-Times/github-label-sync) 一键同步）。

**类型标签 | Type Labels**: `feature` · `enhancement` · `bug` · `documentation` · `performance` · `security` · `ci` · `breaking-change`

**优先级 | Priority**: `priority:critical (P0)` · `priority:high (P1)` · `priority:medium (P2)` · `priority:low (P3)`

**状态 | Status**（维护者专用 maintainer-only）: `status:needs-triage` · `status:triaged` · `status:in-progress` · `status:blocked` · `status:needs-review` · `status:awaiting-feedback` · `status:duplicate` · `status:wontfix`

**模块 | Module**（可叠加 ≤ 3 个）: `mod:monitor`（监控中心）· `mod:ops`（运维管理）· `mod:ai`（AI 智能）· `mod:family`（AI Family）· `mod:devstd`（开发规范）· `mod:admin`（系统管理）· `mod:infra`（基础设施）· `mod:icons`（图标体系）· `mod:docs`（开发者文档）

**使用规则 | Rules**

1. 提交 Issue **必选**：1 类型 + 1 模块 + 1 优先级；模板预置 `status:needs-triage`。
2. 提交 PR **必选**：1 类型 + 1 模块；标题遵循 Conventional Commits。
3. `breaking-change` 必须叠加 `priority:critical|high` 并附迁移说明。
4. 状态标签仅维护者流转，贡献者勿动。
